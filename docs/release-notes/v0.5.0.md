## Pegasus Bridge 0.5.0 (with hub 0.12.0)

Faster after the remote wakes, and easier on its battery. Update both: the Bridge works with an older hub, but the new behaviour needs hub 0.12.0.

### New
- **Sessions survive a lost link.** When the connection to the hub dies while the remote sleeps, or Wi-Fi blinks, the new connection carries on where the old one stopped. Both ends send again what the other missed, so the remote no longer reconnects every integration and asks for everything again, and a button pressed right after waking isn't lost.
- **Fewer check-ins.** Awake and idle, the Bridge checks in with the hub every 15 seconds instead of every 5, and the hub no longer pings the remote on its own. While the remote sleeps nothing is sent at all (it was once a minute). Every check-in wakes the remote's Wi-Fi radio.
- **A dead link is found sooner.** The link is checked the moment the remote wakes (replaced after 0.4 s without an answer, was 1.5 s) and whenever something is sent after a quiet spell. Reconnecting starts at once, then every quarter second.

### Smaller changes
- The Bridge sends the hub only new log lines, changed details and battery readings the hub doesn't have yet, instead of the whole report each time.
- The latency sensor updates at most twice a minute and only when the figure moved; the status text no longer changes with every check-in.
- The hub reads the remote's status once a minute only while the hub page is open, otherwise every 15 minutes.
- Messages written in the same moment (updates held while the remote slept) leave in one network packet.

### Measured on a test bench (8 integrations in use)
| | Before | After |
|---|---|---|
| Messages on an idle link, per minute | 24 | 8 |
| First press after waking on a dead link | 1.8 s | 0.4 s |
| Messages over Wi-Fi for that wake | 69 | 4 |
| Integrations reconnected | 8 | 0 |

Simulated on one machine; figures on a real remote will differ.

### Hub 0.12.0: installing integrations
55 integrations found on GitHub that aren't in the Integration Manager catalog were tested; 37 work ([COMPATIBILITY.md](../../COMPATIBILITY.md)). Fixed on the way:
- a repository with a companion plugin beside the integration (SteamOS HTPC) installs the integration, not the plugin
- a driver that reads `driver.json` from its own `bin` folder (FM-Audio DSP)
- integrations that use modules Python 3.13 removed, such as `telnetlib` (NAD power control)

### Compatibility
- Bridge 0.5.0 with a hub before 0.12.0, and hub 0.12.0 with an older Bridge, work as before (without the new behaviour).

### Updating
1. Pull the latest hub image: `docker pull ghcr.io/sat32blk/pegasus-hub:latest`, then restart the container.
2. On the remote, install `uc-intg-pegasus-bridge-0.5.0.tar.gz` as an **update** to the existing Pegasus Bridge. Don't remove it first, or its pairing is lost.
