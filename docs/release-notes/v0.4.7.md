## Pegasus Bridge 0.4.7

Fixes moves to the hub that stopped while putting an integration's references back into activities.

### Fixed
- **Moves no longer stop on old steps for integrations that are gone.** An activity is saved back as a whole, and the remote refuses it if any step names an entity that no longer exists, even one from a different integration (for example a leftover step for a removed Kodi integration). Before restoring, the Bridge now checks every entity the activities, macros and pages use:
  - **Its integration is no longer on the remote:** the step is left out (it couldn't run anyway), and the move log says which one.
  - **Its integration is set up but the entity is missing** (a device that's off, say): the move stops before changing anything and offers **Continue without it**.
- **Entities the moving integration no longer offers** are checked before anything is written back (from 0.4.6). Ones it doesn't offer are left out, ones it offers are selected again, and anything still missing stops the move with **Continue without it**, instead of failing halfway through.

### Hub page (hub 0.11.1 and 0.11.2)
- A move error's **Details** no longer closes by itself, and its text can be selected while the page refreshes.
- New **Copy** button in Details copies the error and the full move log, for bug reports.
- Errors caused by another integration's entity are explained as such, instead of blaming the integration being moved.

### Updating
1. Pull the latest hub image: `docker pull ghcr.io/sat32blk/pegasus-hub:latest`, then restart the container.
2. On the remote, install `uc-intg-pegasus-bridge-0.4.7.tar.gz` as an **update** to the existing Pegasus Bridge. Don't remove it first, or its pairing is lost.
3. If a move stopped earlier, open the hub page and press **Retry** on it.
